Na komputerze klienta wybierz tę rolę. Program działa jako Server i udostępnia podłączony interfejs.

AutoTunel.exe

Diagnosta

Na swoim komputerze wybierz tę rolę. Program działa jako Client i podłącza zdalny interfejs.

AutoTunel.exe

1. Jednorazowe przygotowanie

Skopiuj ten sam AutoTunel.exe na oba komputery. Oba komputery muszą mieć Windows 10/11 x64 (przy samochodzie: od 1809; diagnosta: od 1903), .NET Framework 4.8 oraz połączenie w tej samej sieci RadminVPN. Program poprosi o uprawnienia administratora.

Przy samochodzie

Wybierz tę rolę i USB. AutoTunel sam przygotuje obsługę USB z pliku EXE, a następnie pokaże interfejsy.

U diagnosty

Wklej kod i kliknij Połącz z samochodem. AutoTunel przygotuje USB automatycznie. Zachowaj sterownik swojego Openporta.

Pakiety USB i potrzebny runtime klienta są wbudowane w ten EXE. Przygotowanie nie pobiera ich z Internetu i nie wymaga osobnego uruchamiania instalatorów. Możesz wykonać je wcześniej przez Ustawienia USB → Przygotuj USB. Kolejne uruchomienia korzystają z gotowej instalacji. Nie potrzeba WSL, Pythona, .NET SDK ani pliku .exe.config.

Jednorazowy restart: po pierwszym przygotowaniu USB u diagnosty wybierz w Windows Uruchom ponownie i otwórz AutoTunel ponownie. Program pokaże, kiedy jest to potrzebne, i nie zrestartuje komputera samodzielnie. Windows musi zainstalować sterownik w systemie; AutoTunel wykonuje tę czynność automatycznie.

2. Udostępnij przy samochodzie

  1. Podłącz Openport do USB i samochodu. Zwolnij go w innych aplikacjach, w tym VirtualHere.
  2. Uruchom AutoTunel.exe i wybierz rolę Przy samochodzie. Wybierz USB i właściwy Openport. Pojedynczy rozpoznany interfejs oraz adres RadminVPN są wybierane automatycznie.
  3. Kliknij Udostępnij interfejs. Zaczekaj na komunikat gotowości i pojawienie się kodu.
  4. Kliknij Kopiuj kod i przekaż go prywatnie diagnoście. Pozostaw program otwarty.

3. Połącz na swoim komputerze

  1. Uruchom AutoTunel.exe, wybierz rolę Diagnosta, kliknij Wklej kod, potem Połącz z samochodem.
  2. Tryb i urządzenie zostaną pobrane z kodu. Zaczekaj na potwierdzenie podłączenia USB.
  3. Sprawdź Openport w Menedżerze urządzeń, następnie wybór interfejsu, identyfikację i odczyt w Xentry PassThru.
  4. Po zakończeniu diagnostyki kliknij Rozłącz. Nowa sesja wymaga nowego kodu.
Kod AMB4 zawiera sekret sesji. Przekazuj go prywatnie i nie umieszczaj w raportach. Komunikat „USB podłączone” potwierdza podłączenie sterownika, a zgodność z Xentry wymaga osobnego sprawdzenia.

Obsługa USB w jednym miejscu

Program sam wykrywa lokalną obsługę USB. Zachowuje zgodne instalacje i wcześniejsze ustawienia obu ról w %LOCALAPPDATA%\AutoTunel-MB\settings.json. Licencje są dostępne przez Ustawienia USB → Licencje składników USB. Kody i sekrety sesji nie są zapisywane w ustawieniach.

Oddzielne dzienniki odzyskiwania powstają podczas pracy z USB. Pozwalają zwolnić własne urządzenie po przerwaniu programu.

ENET

Server korzysta z dedykowanej karty Ethernet do auta i Npcap x64. Client korzysta z TAP-Windows6 (tap0901). Kod dobiera tryb automatycznie, a tunel przenosi również ARP i broadcast. Karta auta nie może być kartą z bramą internetową.

Adresację TAP trzeba jeszcze przygotować dla danej sieci samochodu. Ten tryb nie emuluje J2534 i wymaga programu obsługującego ENET/DoIP.

Błąd instalatora 1639

Ta wersja poprawia nieprawidłowy zapis polecenia instalatora MSI. Zamknij poprzedni AutoTunel i uruchom nowy plik. Wybierz Przy samochodzie, a jeśli przygotowanie nie ruszy automatycznie — Ustawienia USB → Napraw USB.

Naprawa USB i Windows LTSC

Przy samochodzie obsługiwany jest Windows 10 1809 (LTSC 2019, build 17763) lub nowszy. Diagnosta wymaga 1903 (build 18362). Po nieudanej instalacji zamknij starszy AutoTunel, uruchom ten EXE i wybierz Ustawienia USB → Napraw USB. Zakończ wcześniej sesje i zwolnij własne USB. Naprawa sprawdza aktywne połączenia, VirtualBox i wersję instalacji.

Przycisk Diagnostyka USB na dole okna otwiera zachowane informacje o Windows, architekturze, wersjach i błędach instalatora. Jeśli poprzednia wersja pozostawiła żądanie restartu, uruchom ponownie Windows. Instalatory i sterowniki pozostają oryginalne.

Gdy coś nie działa

  • Brak RadminVPN: sprawdź połączenie obu komputerów z tą samą siecią i odśwież listę.
  • Brak USB lub sterownika: otwórz Ustawienia USB i wybierz Napraw USB przy samochodzie lub Przygotuj USB u diagnosty. Po komunikacie o restarcie uruchom ponownie Windows. Szczegóły zawierają ścieżkę do dziennika przygotowania.
  • Urządzenie zajęte: zakończ używanie go w VirtualHere i innych aplikacjach.
  • Niepoprawny kod: korzystaj z tej samej wersji AutoTunel na obu komputerach. Skopiuj nowy, pełny kod AMB4.
  • Przerwane połączenie: sprawdź przewód i RadminVPN, następnie rozpocznij nową sesję. Program nie ponawia podłączenia automatycznie.
  • Uszkodzone ustawienia: zachowaj kopię settings.json, zmień nazwę tego pliku i ponownie otwórz AutoTunel. Obsługa USB zostanie wykryta automatycznie. Aplikacja nie nadpisuje uszkodzonego zapisu.
  • Pozostałość po awarii: użyj przycisku Zwolnij USB po awarii. Program zwalnia tylko zapisane własne udostępnienie lub lokalne podłączenie.

Sieć i Zapora Windows

Ta wersja jest przygotowana do pracy z wyłączoną Zaporą Windows. AutoTunel nie włącza ani nie wyłącza zapory i nie wymaga skryptu konfiguracji. Przy pierwszym przygotowaniu oficjalny instalator usbipd-win tworzy swoją standardową regułę zapory. Sesja AutoTunel korzysta z TCP 24832 na wybranej karcie RadminVPN.

Usługa usbipd-win nasłuchuje także na TCP 3240 na interfejsach sieciowych. Przy wyłączonej zaporze inne komputery z dostępem do tego portu mogą podłączyć udostępnione USB bez kodu AutoTunel i poza jego tunelem TLS. Używaj zaufanej sieci; RadminVPN nie blokuje dostępu przez pozostałe karty. Nie przekierowuj portu 3240 na routerze. Starsze reguły AutoTunel pozostają bez zmian.

Co sprawdzono

Kompilację EXE x64, automatyczne testy transportu, USB/IP i polityki przygotowania oraz integralność obu pakietów zapisanych w EXE. Testy uruchomiono w Linux. Nie uruchomiono instalatorów, restartu, GUI, sterowników USB/IP ani fizycznego Openporta/Xentry na Windows. Pełny scenariusz pierwszej próby jest w WINDOWS-TEST.md; wyniki testów w TESTY.txt.

Pierwsza próba obejmuje identyfikację i odczyt. Gotowość do programowania ECU wymaga osobnej oceny po testach sprzętowych. Pozostałe interfejsy i programy nie mają jeszcze potwierdzonej zgodności.
